# AI 突然挂了怎么办？一个真实的应急预案

## 一句话答案
不要把鸡蛋放在一个 AI 里。AI 宕机、断网、限流、模型变傻——不是你倒霉，是必然发生的事。备好预案的人能继续干活，没备好的人只能干等。

## 适用场景
- AI 聊天框突然报错
- 某个模型今天回答质量明显下降
- 晚上赶工，发现服务在维护
- 公司突然封锁了 AI 外网访问

## 为什么这是"高"风险 — 因为你正在把核心工作押在一家服务商上

如果你的工作流已经深度绑定 AI——日报靠 AI、方案靠 AI、数据分析也靠 AI——那么 AI 挂掉的那一刻，你的产出也就停了。

这不是假设：

- **2024 年 OpenAI 多次大规模宕机**，ChatGPT Plus 用户集体断联数小时
- **Claude 免费版限流**，高峰期对话直接被截断
- **DeepSeek 短期大热后频繁进入"繁忙"状态**
- **模型版本更新**，同一个 Prompt 昨天好使今天变蠢
- **公司网络策略变更**，非预期屏蔽海外 API 端点

每一次都是"早知道……"现场。

## 预案总纲：四条腿走路

### ① 至少备 2 个 AI 工具，不同家

不要只注册一个 AI 账号。理论上你不需要同时付费，但手上至少有 2-3 个工具随时能用：

| 类别 | 推荐备选 |
|------|---------|
| 主力（你要用它干活） | DeepSeek / Kimi / 豆包 |
| 备份（主力挂了用它） | 通义千问 / 智谱清言 |
| 保底（断网也能用） | 本地模型（Ollama + 小模型，见下文） |

**选不同家的更安全。** 同一个底层模型（比如都用了 DeepSeek 的 API）会一起挂。

### ② 每天 30 秒预备：把你的 Prompt 存成文件

这个问题最根本的解决方案不是找更强的 AI，是 **把你的输入标准化**。

你每天要 AI 做的事情——写周报、分析数据、改文案——应该形成一套固定的 Prompt。存成文件放在桌面：

```
~/ai-prompts/
├── 周报写作.txt
├── 数据分析.txt
├── 文案改写.txt
└── 信息整理.txt
```

AI 挂了你就换个工具，把同样的 Prompt 贴进去。**变的是模型，不变的是你的方法。**

### ③ 本地模型保底（不要慌，一个笔记本就能跑）

不是要你部署 70B 大模型。你需要的只是在断网或服务全部挂掉时还能继续做些基础工作。

**推荐配置：** Ollama + qwen2.5:7b

```bash
# 安装
curl -fsSL https://ollama.com/install.sh | sh
ollama pull qwen2.5:7b

# 用的时候（不需要网络）
ollama run qwen2.5:7b
```

7B 模型在 M1/M2 Mac 或任何有 8GB 显存的显卡上都能流畅运行。写个方案大纲、列个检查清单、改个短文案——绰绰有余。

**如果你连命令行都不想碰：** LM Studio（有 UI，Windows/Mac 都支持）

### ④ 把关键输出存到本地，不要留在 AI 对话里

很多人把 AI 聊天记录当"项目文件"。但 AI 服务一关——数据全丢。

- 每次对话结束后，把 AI 的回答存成本地文件
- 重要的方案、代码、分析结果从 AI 对话里摘出来，放到项目目录
- 每周五花 5 分钟，检查这一周 AI 相关的产出有没有落盘

## 应急预案分级（根据严重程度行动）

### 绿 — 轻度异常
> 模型回答了但质量下降，或者响应变慢

**行动：** 不要死磕。换另一个模型试同样的 Prompt。如果质量差不多，就是这个任务本身不好。如果另一个模型正常，说明主力模型今天抽风。

### 黄 — 中度异常
> 主力 AI 频繁报错、限流、或大面积不可用

**行动：**
1. 切到备选工具（Kimi / 豆包 / 通义千问）
2. 把你在主力上的 Prompt 贴进去继续
3. 今天的 AI 产出量减半，多给自己留复核时间

### 红 — 重度异常
> 所有在线 AI 都挂了 / 公司断网 / API Key 失效

**行动：**
1. 启动本地模型（Ollama / LM Studio）
2. 只做"扩展"类工作（写大纲、列要点、改写），不做"判断"类工作
3. 今天的人工复核比例提到 100%

### 黑 — 灾难级
> 以上三种手段全部失效

**行动：** 纯人工。但因为你之前有标准化 Prompt 文件 + 本地存了关键产出，你至少知道要做什么、从哪里继续。

## 防翻车检查清单

### ✅ 今天就做的事（30 分钟）
- [ ] 注册了至少 1 个备份 AI（和主力不是一个公司）
- [ ] 把常用 Prompt 存成了本地文件
- [ ] 安装了本地模型（Ollama + qwen2.5:7b，约 15 分钟）

### ✅ 每周做的事（5 分钟）
- [ ] 检查 AI 产出的关键文件是否已落盘
- [ ] 更新一次本地模型到最新版本（`ollama pull qwen2.5:7b`）

### ✅ 每月做的事（10 分钟）
- [ ] 测试一次备份工具的可用性（直接跑一个真实的 Prompt）
- [ ] 检查本地模型是否还能正常启动
- [ ] 删除不用的 AI 账号中遗留的敏感信息

## 可复制 Prompt

```text
假设所有联网 AI 都不可用了。我只剩本地模型（7B 参数级别）。
请帮我整理一份 [任务名称] 的核心框架和大纲，
只说事实和结构，不编造具体数据。
关键判断点列出来，我自己决定。
```

## 可复制 Skill

**Skill：** AI 容灾预案助手
**场景：** AI 服务中断、模型降级或断网时，保证核心工作不中断
**风险等级：** 🔴 高

**指令：**
```text
假设所有联网 AI 都不可用了。我只剩本地模型（7B 参数级别）。
请帮我整理一份 [任务名称] 的核心框架和大纲，
只说事实和结构，不编造具体数据。
关键判断点列出来，我自己决定。
```

**约束：**
- 不编造具体数据或数字
- 只提供框架性内容（大纲、结构、要点）
- 所有判断点留给用户自己做
- 标注需要联网或专业工具才能完成的部分

**输出检查：**
- [ ] AI 没有编造具体数据？
- [ ] 框架结构完整，可以直接复用？
- [ ] 判断点标注清楚了？
- [ ] 标注了哪些步骤需要联网/专业工具？

## 结论

AI 不会永远在线，也不会永远好用。这不是 AI 不靠谱，是任何服务都这样。

跟备份手机数据、准备备用电源一个道理——你不需要每天都用它们，但是出事那天，你会庆幸自己提前准备了。

**核心就是四条：**
1. 多模型（主力 + 备份 + 本地）
2. 标准化输入（Prompt 存文件，随换随用）
3. 输出落地（不留在 AI 对话里）
4. 分级预案（知道什么程度做什么事）
